Guía de usuario de LunaDev POS

Instalación, operación, conexión del dueño, pruebas y mantenimiento. Edición de pruebas del 12 de octubre de 2026 para Windows de 64 bits.

LunaDev POS guarda la información completa del negocio en la computadora del local. La página del dueño recibe una copia de los reportes en Cloudflare. Esta guía explica cómo configurar ambas partes y cómo conservar la información cuando reinstalas. Una página de reportes no sustituye el respaldo completo del negocio.

1 Qué archivos necesitas

  • Instalar-LunaDevPOS-Limpio.exe: instala el programa; permite conservar datos o comenzar desde cero con copia de seguridad.
  • Desinstalar-LunaDevPOS.exe: retira LunaDev POS y las versiones Nuvaria anteriores. Sirve también cuando la versión antigua no aparece en Windows.
  • Kit-Pagina-LunaDevPOS.zip: publica una página central nueva en la cuenta de Cloudflare de un negocio. Se utiliza en tu computadora como desarrollador, no en cada caja.
  • Este manual: puedes abrir la versión HTML y usar Imprimir → Guardar como PDF.

El instalador no lleva productos, ventas, clientes, logo del negocio, correo del dueño ni claves de servicios. Los datos que aparecen tras una actualización proceden de la instalación anterior que conservaste.

2 Entender las tres partes

Computadora del local: tiene el programa y su base SQLite. Aquí se venden productos, se cambia el inventario, se administran clientes y se hacen cortes. Las ventas locales no dependen de que Cloudflare esté conectado.

Página del dueño: se publica como un servicio de Cloudflare Workers, con sus archivos visuales y una base Cloudflare D1 que conserva los reportes. Puede consultarse desde un teléfono con Wi-Fi o datos, o desde una computadora. No necesitas comprar un servidor físico para esta prueba. Workers y su dirección workers.dev, base D1.

Cuenta de Cloudflare: pertenece al dueño o negocio y administra ese alojamiento. Crear una cuenta no publica el programa automáticamente: debes ejecutar la publicación inicial con el kit. Un cliente nuevo utiliza una página y una base propias, separadas de las de otro cliente. Las sucursales de ese mismo negocio se conectan a su misma página.

Cuando el local se apaga, la página central conserva la última información recibida. No recibirá ventas nuevas mientras la computadora no esté funcionando y conectada. Al volver a abrir, el POS envía sus datos otra vez. Revisa siempre la fecha y la hora de la última copia de cada local.

3 Diferenciar las cuentas y claves

  • Cloudflare: correo y contraseña del alojamiento. Se usan para entrar a su panel y autorizar la publicación.
  • Dueño en la página central: correo y una clave central aleatoria generada al publicar. Esta clave no es la contraseña de Cloudflare ni la del mostrador.
  • Administrador del POS: usuario y contraseña que creas en la computadora al configurar el negocio por primera vez.
  • Vendedores y supervisores: usuarios del POS creados desde Usuarios y permisos.
  • Clave de sucursal: código largo generado en la página central para vincular una computadora/local. No permite entrar como dueño. Cada local tiene su propia clave.
  • Facturama sandbox: credenciales del proveedor de facturación para sus pruebas. No se usan para Cloudflare ni para iniciar turno.

No sustituyas una clave central o de sucursal por una palabra corta: el sistema actual las trata como claves aleatorias. Guarda los archivos privados de configuración del dueño. No los incluyas en un instalador que entregarás a otro cliente.

4 Empezar desde cero en una computadora con pruebas anteriores

  1. Termina el turno y cierra todas las ventanas de LunaDev POS y sus versiones anteriores.
  2. Si quieres conservar la prueba, abre Administración → Mantenimiento → Exportar respaldo completo y guarda el archivo fuera de la computadora antes de cerrar.
  3. Ejecuta Desinstalar-LunaDevPOS.exe.
  4. Selecciona Empezar de cero: quitar el programa y archivar los datos y pulsa Desinstalar.
  5. Apunta la carpeta del respaldo que te indique. Se encuentra en LunaDevPOS-Respaldos, dentro de tu carpeta de usuario de Windows. Copia esa carpeta a una USB si quieres conservarla ante un formateo.
  6. Ejecuta Instalar-LunaDevPOS-Limpio.exe. Si aún quedan datos de una instalación anterior, selecciona Empezar desde cero y archivar los datos anteriores.
  7. Pulsa Instalar / actualizar y, al terminar, Abrir programa.
  8. Debe aparecer la creación inicial del negocio y su cuenta de administrador. Si entra directamente a una cuenta o muestra ventas anteriores, detente: revisa si elegiste conservar datos o si abriste un acceso viejo.

Se archivan las carpetas completas, incluida la vinculación anterior y los datos del navegador integrado. También se genera un respaldo portable .botica.json cuando existe una cuenta activa con permiso de respaldos. La carpeta datos-originales conserva los archivos originales; no es necesario borrarla para que la instalación nueva empiece vacía.

El desinstalador reconoce únicamente LunaDev POS y las versiones anteriores de este proyecto. No retira el punto de venta de otro proveedor ni la carpeta de código fuente de tu proyecto. No borra reportes en Cloudflare.

5 Instalar en una computadora nueva

  1. Copia el instalador a la computadora de Windows de 64 bits.
  2. Ejecuta el instalador con la cuenta de Windows que utilizará el negocio.
  3. En una computadora sin datos anteriores, la instalación empezará vacía. Deja Instalar o actualizar conservando mis datos; no hay datos que conservar.
  4. Al terminar, abre LunaDev POS desde el escritorio.
  5. Escribe el nombre del negocio. Crea su usuario administrador y una contraseña nueva de al menos ocho caracteres; repítela para confirmar.
  6. Guarda esas credenciales de forma privada. No se crea automáticamente un usuario por poner un correo en la conexión.

Tras instalar esta versión, LunaDev POS aparecerá en la lista de aplicaciones de Windows para desinstalarlo. Las versiones antiguas no aparecían porque su instalador solo copiaba archivos y creaba un acceso directo.

El programa incorpora su motor de escritorio; no necesitas instalar Python o Node.js en las cajas. Esta entrega es de pruebas para Windows de 64 bits. Comprueba su funcionamiento en la computadora concreta, especialmente impresora, escáner y rendimiento durante un día de prueba.

6 Personalizar el negocio

Abre Menú → Configuración. Introduce el nombre y logo del negocio y revisa los datos y mensaje del ticket. La marca LunaDev POS corresponde al programa; el nombre del negocio y su logo se configuran para cada cliente.

Revisa la vista previa del ticket antes de probar la impresión. La configuración de la impresora de Windows y su tamaño de papel debe corresponder con tu impresora real. Haz una impresión de prueba sin utilizarla como comprobante fiscal.

7 Cargar el inventario del sistema que ya usa la farmacia

  1. En el punto de venta del otro proveedor, busca su opción de exportar inventario. El nombre exacto depende de ese sistema; no podemos suponer su menú.
  2. Guarda una copia del archivo original y trabaja con otra copia para adaptar columnas. No cambies su base directamente.
  3. Si exporta un libro Excel .xlsx o .xls binario, ábrelo en Excel y guárdalo como CSV. Esta versión importa CSV, el XLS de texto compatible del sistema anterior y el JSON de inventario de LunaDev; no abre directamente libros Excel binarios ni XML de otros proveedores.
  4. La tabla CSV debe tener estas columnas: Codigo, Descripcion, Precio Costo, Precio Venta, Precio Mayoreo, Inventario, Inv. Minimo, Departamento.
  5. Conserva Codigo como texto para no perder ceros iniciales. Precio Costo es el costo unitario; Precio Venta es el precio al cliente; Inventario es la cantidad disponible; Inv. Minimo es el punto de reorden. Usa punto para los centavos, por ejemplo 20.50, y revisa precios en la vista previa si Excel usa coma decimal.
  6. Abre Administración → Mantenimiento → Importar inventario. Selecciona el archivo y revisa la vista previa, errores y cantidades antes de confirmar.
  7. Busca varios productos por código y comprueba nombre, precio y stock contra el sistema original. No importes el mismo stock dos veces; revisa el efecto que indica la vista previa.

Una tabla agrupada de inventario no conserva el costo histórico de cada lote, sus fechas ni las ventas del otro programa. Si ambos sistemas usan costos históricos distintos, su ganancia puede diferir aunque cobren lo mismo. Para migrar desde otra instalación de LunaDev, usa Inventario JSON o el respaldo completo, según los datos que necesitas conservar.

8 Usuarios y permisos

Administración tiene botones Proveedores, Clientes y Usuarios y permisos. Desde ellos puedes crear, editar y dar de baja. La baja es reversible y conserva compras, ventas y movimientos históricos. Un cliente con saldo pendiente no puede darse de baja; un usuario debe cerrar su turno primero y no puedes retirar la cuenta con la que estás trabajando. Para reactivar un usuario, edita su ficha y marca Activo.

Los proveedores se seleccionan por nombre, sin escribir su ID. Nombre del proveedor o empresa es obligatorio; persona de contacto y teléfono son opcionales. En clientes se captura nombre y teléfono; el descuento queda como opción adicional. Para volver a utilizar un proveedor o cliente de baja, usa Reactivar una baja.

En Administración → Usuarios y permisos, utiliza Crear / editar usuario. Elige vendedor, supervisor o administrador como plantilla y revisa cada permiso antes de guardar. Puedes ajustar los permisos de la plantilla.

Cada trabajador debe usar su propia cuenta. El usuario recordado puede completarse con Tab; la contraseña no se guarda mediante esa función. Las contraseñas anteriores no se muestran: el administrador puede asignar una nueva desde la edición del usuario.

9 Abrir el turno

Inicia sesión, selecciona el turno y registra el efectivo físico inicial que dejas en la caja para cambio. No pongas las ventas del día anterior, salvo que ese importe esté realmente en el cajón como fondo inicial.

Ejemplo: si comienzas con $200 en billetes y monedas, introduce $200. Si comienzas sin efectivo, introduce $0. Debes cerrar tu turno antes de salir normalmente.

10 Vender y cobrar

Busca o escanea el producto, revisa su cantidad y selecciona el cliente si corresponde. Confirma los precios y descuentos antes de cobrar.

En Cobrar elige Efectivo, Tarjeta, Transferencia o Crédito. La modalidad seleccionada queda marcada visualmente. En efectivo, introduce el dinero recibido y entrega el cambio indicado. Tarjeta y transferencia deben cubrir el importe exacto.

Si utilizas Mercado Pago, confirma que la terminal o Tap aprobó el pago antes de confirmar la venta en LunaDev. El POS registra la venta, pero no procesa la tarjeta ni consulta automáticamente Mercado Pago.

11 Comisiones de Mercado Pago

En Administración → Comisiones de tarjeta, pulsa Usar referencia Mercado Pago y revisa la tarifa de tu cuenta antes de guardar. Activa Aplicar esta tarifa a cobros nuevos con tarjeta.

La referencia publicada para Point y Point Tap al contado, consultada el 12/10/2026, es 3.5 % más IVA. En $100, la comisión estimada con IVA es $4.06 y el neto estimado $95.94. Point, Point Tap.

El cliente sigue pagando $100. La venta total sigue siendo $100. El bloque de comisiones muestra por separado lo descontado y lo que recibirías. La tarifa queda guardada con cada venta y abono; cambiarla no recalcula el pasado.

Es una estimación: promociones, meses sin intereses, retenciones y otros ajustes requieren revisar el estado de cuenta del proveedor. No se supone que la comisión se reembolse automáticamente cuando devuelves un producto. Los cobros antiguos sin tarifa histórica se indican como incompletos.

12 Clientes y créditos

En Clientes - Créditos, registra al cliente y sus datos. Desde el carrito, al cobrar selecciona Crédito y elige quién debe esa compra. Se reduce el stock y aumenta su deuda; no se suma dinero recibido hasta que abone.

Para cobrarle, abre su cuenta y pulsa Registrar abono. El abono reduce el saldo total, aunque no pague medicamentos concretos. Si debe $315 y entrega $350 en efectivo, se aplican $315 y se entregan $35 de cambio. En tarjeta o transferencia no se acepta un importe superior al saldo.

Puede pedir otra compra a crédito antes de saldar; se agrega a su cuenta. Los abonos con tarjeta también conservan su comisión estimada. Una venta con descuento del 100 % registra ticket y unidades con importe cero; no genera dinero cobrado.

13 Recibir mercancía y editar productos

En Inventario puedes buscar y pulsar Editar producto o Ajustar existencia junto al resultado. Ajustar existencia establece el conteo real de unidades vendibles y registra la diferencia con un motivo y usuario; no registra una compra nueva. Recibir mercancía suma unidades que llegaron.

Si hay varios lotes, cuenta sus unidades por separado para conservar costos y caducidades. Los caducados y la cuarentena no se incluyen en el conteo vendible. Si ocurrió una venta, recepción o cambio de ficha durante el conteo, el ajuste se bloquea y debes reabrirlo. La edición de nombre y precio no cambia las partidas de los tickets anteriores.

El botón Editar producto de Administración permite buscar por nombre o código y seleccionar una coincidencia para abrir su formulario; no se queda en una tabla de resultados.

Nuevo producto registra un producto que todavía no existe. Recibir mercancía busca uno existente por nombre o código para agregar unidades. Revisa stock actual y stock después de la entrada. Los datos del producto se modifican desde Editar producto.

El punto de reorden es la existencia a partir de la cual el sistema avisa para revisar reposición. La existencia máxima sirve como referencia para sugerir cuánto pedir. Las fechas y lotes se capturan cuando se conocen; una fecha no capturada no equivale a una comprobación de que el producto no caducó.

14 Entradas y salidas de caja

Registra Entradas de efectivo cuando agregas dinero que no procede de una venta, y Salidas para retiros, resguardo o pagos que salen del cajón. Escribe un motivo claro.

Estos movimientos afectan el efectivo esperado del corte, pero no se suman a ventas. Se consultan en Historial → Entradas y salidas y en el Excel completo. No uses una entrada de caja para registrar otra vez una venta ya cobrada.

15 Leer el historial

Selecciona Desde y Hasta y pulsa Consultar. Pasa el cursor o enfoca un bloque para ver su explicación.

  • Ventas totales: dinero cobrado por ventas y abonos menos devoluciones. No incluye créditos pendientes ni movimientos extraordinarios de caja.
  • Ganancia real: ventas cobradas menos costo histórico correspondiente a los productos. Este bloque es el margen del producto, antes de la comisión de tarjeta.
  • Cobros antes de devoluciones: dinero recibido antes de restar devoluciones.
  • Costo correspondiente a lo cobrado: costo de compra reconocido en lo que ya cobraste; en abonos, la parte proporcional.
  • Total de formas de pago: suma de efectivo, tarjeta y transferencia netos de devoluciones.
  • Neto después de comisiones: ventas totales menos la comisión estimada.
  • Ganancia después de comisiones: margen del producto menos esa comisión. No calcula salarios, todos los gastos ni utilidad fiscal.
  • Tickets: tickets registrados; un abono no crea otro ticket de venta.

Por día compara jornadas. Por producto muestra qué productos se movieron. Detalle de movimientos muestra ticket y partida. Entradas y salidas muestra dinero extraordinario del cajón. Comisiones de tarjeta muestra cada cobro y su tarifa.

Descargar Excel completo genera un archivo del periodo con cinco hojas. Los CSV de detalle y resumen diario tienen objetivos distintos y no cambian con la pestaña seleccionada. Para conservar todas las vistas, utiliza Excel completo. Exportar reportes no reemplaza Exportar respaldo completo.

16 Cerrar el turno

Cuenta exclusivamente billetes y monedas del cajón e introduce ese importe en Efectivo contado. No copies el total de ventas: parte pudo pagarse por tarjeta o transferencia, y puede existir fondo inicial, entradas o salidas.

Ejemplo: fondo inicial $200, ventas en efectivo $100, tarjeta $100, retiro $50. El efectivo esperado es $250. Declarar $250 da diferencia cero, aunque las ventas totales sean $200.

El corte compara efectivo contado con efectivo esperado. Después puedes cerrar sesión y el programa. Si hubo apagón o un cierre abrupto y quedó un turno pendiente, utiliza la recuperación de turno con tu cuenta autorizada; no inventes un conteo para quitar un error.

17 Comparar con el punto de venta original durante un día

  1. Mantén el sistema original como registro principal durante la prueba.
  2. Antes de comenzar, verifica que ambos tengan iguales precios, cantidades y descuentos de prueba. Revisa sus fondos iniciales.
  3. Registra cada operación en ambos sistemas, usando la misma forma de pago y cantidad. Cobra la tarjeta una sola vez: registrar en dos sistemas no significa realizar dos cargos en la terminal.
  4. Registra también abonos, devoluciones, entradas y salidas que quieras comparar. No mezcles operaciones de antes de abrir el turno de prueba.
  5. Anota diferencias en cuanto aparezcan: producto, ticket, hora, cantidades, descuento y método de pago. Si hay un fallo, no vuelvas a confirmar a ciegas.
  6. Al cierre compara ventas cobradas por medio, créditos pendientes, abonos, devoluciones, efectivo físico, stock y diferencias. Compara comisiones solo si ambos programas usan la misma tarifa.
  7. Exporta Excel completo y respaldo completo. Guarda los archivos con fecha y nombre del local.

Puede ser más lento introducir cada compra dos veces. Prueba primero algunas ventas sencillas y comprueba que la computadora puede mantener ambos programas abiertos sin afectar el cobro principal. No hay sincronización automática con el programa del otro proveedor.

18 Publicar la página de un cliente nuevo

Este paso se realiza una sola vez por negocio. Para conectar otra sucursal del mismo dueño, ve directamente a la sección siguiente: no publiques otra página.

  1. El dueño crea una cuenta gratuita en Cloudflare y conserva su contraseña. Tú puedes acompañarlo, pero no necesitas conocer su contraseña para instalar el POS.
  2. En tu computadora de configuración, instala Node.js LTS desde https://nodejs.org si todavía no lo tienes. Esta herramienta es para publicar; no se instala en cada caja.
  3. Extrae Kit-Pagina-LunaDevPOS.zip en una carpeta nueva para ese cliente. No reutilices la carpeta privada de otro negocio.
  4. Abre Crear-pagina.cmd. Aparecerá una ventana de preparación que pide un nombre corto del negocio y el correo del dueño. Es un asistente de publicación, no la ventana del mostrador.
  5. El configurador abre Cloudflare. Inicia sesión con la cuenta correcta y autoriza la conexión. Revisa la cuenta que muestra la herramienta y escribe CONTINUAR únicamente si corresponde a ese negocio.
  6. Espera a que cree la base de reportes, publique la página y configure su acceso. No cierres la ventana mientras trabaja.
  7. Al terminar se genera DATOS-PRIVADOS-DEL-DUENO.txt. Guarda el correo y la clave central de forma privada. No entregues toda esa carpeta a otro cliente: contiene autorización de Cloudflare y datos de esa instalación.
  8. Abre el panel de Cloudflare → Workers y Pages → el servicio con el nombre que indica el archivo privado. En Domains and Routes, copia la dirección HTTPS terminada en workers.dev.
  9. Abre esa dirección e inicia sesión con el correo y la clave central del archivo. Todavía no verá productos: falta vincular su primer local.

El configurador crea un nombre nuevo para evitar reemplazar la página existente de otro negocio. No requiere un dominio de pago para esta prueba. Los planes gratuitos tienen límites; revisa capacidad y condiciones antes de comercializar a negocios grandes. Para actualizar la página que ya creaste, conserva su carpeta y usa Actualizar-pagina.cmd, que no crea otra base ni vuelve a generar claves.

Si la publicación falla, no asumas que terminó: conserva el mensaje y revisa qué recursos quedaron creados en esa cuenta antes de repetir. No borres bases de otros negocios. Para comprobar los comandos y requisitos, consulta Wrangler y D1.

19 Conectar el primer local

  1. Entra en la página central del dueño. Abre Menú → Configuración.
  2. Crea una sucursal con un nombre identificable, por ejemplo Local Centro. Copia su clave de vinculación y guárdala temporalmente en privado.
  3. En LunaDev POS de esa computadora, abre Menú → Configuración → Cuenta del dueño · Sucursales y enlace fijo.
  4. Introduce la dirección HTTPS de la página central, sin /direccion/ ni códigos adicionales, el nombre del local y su clave de sucursal.
  5. Guarda y comprueba el mensaje de conexión. Espera a que termine el envío del historial; puede requerir varios ciclos si hay muchas fechas.
  6. En el teléfono, abre la dirección del dueño. Usa el correo y la clave central, no el usuario del vendedor ni la clave de sucursal.
  7. Selecciona el local y comprueba una venta de prueba contra la computadora.
  8. Prueba desde datos móviles u otra red. El enlace fijo funciona por internet; no se limita al Wi-Fi del local.

El POS envía información aproximadamente cada 15 segundos y el panel consulta aproximadamente cada 10 segundos mientras está visible. Es actualización periódica, no una transmisión instantánea de cada tecla. La lectura conserva sección y scroll. Revisa el estado de conexión y última copia si algo parece detenido.

20 Agregar más sucursales

Instala el programa en el segundo local, configura su negocio, inventario y usuarios, crea otra sucursal en la misma página central y utiliza su propia clave. Repite para los siguientes locales.

Cada sucursal mantiene caja e inventario propios. El selector permite revisar una o Todos los locales. Los generales suman ventas y márgenes de los locales seleccionados, sin convertir sus inventarios en una caja compartida. Si falta información de un local, no des por completo el total.

No copies la base de clientes, ventas ni la clave de conexión de una sucursal sobre otra para agregarlas. Para un cliente empresarial diferente, utiliza una página/base independientes y sus credenciales propias.

21 Usar tu cuenta de pruebas actual otra vez

Puedes conservar tu cuenta actual de Cloudflare y su página existente. Tras limpiar el POS, esa página seguirá mostrando los reportes anteriores porque no se borran al desinstalar.

Para una prueba realmente separada, crea una sucursal nueva llamada, por ejemplo, Prueba jornada 12 octubre, y selecciona únicamente esa sucursal al comparar. Si quieres que Todos los locales no mezcle pruebas antiguas, exporta primero sus reportes y desactiva las sucursales viejas desde Configuración central.

Desactivar las retira del selector y bloquea sus conexiones; no formatea la base cloud. No existe actualmente un botón de reactivación en esa pantalla, así que no uses Desactivar durante mantenimiento si quieres conservar esa sucursal operativa.

Si quieres simular también una página completamente nueva, ejecuta el kit en una carpeta nueva, autorizándolo con tu misma cuenta de pruebas. Creará otro servicio y otra base, con otro enlace. No es obligatorio para la prueba diaria de un local.

22 Qué ocurre al desinstalar o borrar el mostrador

Desinstalar la aplicación no elimina sus datos por defecto. La opción de comenzar de cero los archiva aparte. Ninguna de esas acciones borra reportes en Cloudflare.

La página puede seguir mostrando la última copia recibida aunque el programa ya no exista en la computadora. Eso no significa que el programa se esté ejecutando. Cuando vinculas una nueva instalación al mismo local, su nueva copia puede reemplazar las cifras actuales de ese local; por eso debes restaurar antes de conectar durante un mantenimiento.

La copia central no contiene todo lo necesario para reconstruir la caja: no sustituye clientes, deudas y abonos completos, cuentas y permisos, registros internos ni la configuración local. Mantén respaldos completos del POS fuera de la computadora.

23 Mantenimiento sin perder información

  1. Cierra el turno y comprueba los totales. Exporta Excel si necesitas conservar los reportes visibles del periodo.
  2. En Administración → Mantenimiento, exporta Respaldo completo y verifica que descargó un archivo .botica.json. Guárdalo en una USB o ubicación fuera del equipo que vas a formatear.
  3. Anota la dirección de la página central y el nombre de esa sucursal. Conserva por separado el acceso del dueño. No pulses Desactivar esa sucursal.
  4. Cierra el programa. Puedes desinstalar con la opción de conservar datos; si vas a formatear Windows, necesitas el respaldo externo aunque hayas conservado las carpetas locales.
  5. Después del mantenimiento, instala el POS. Crea una cuenta temporal si la instalación está vacía, pero no importes stock ni abras un turno.
  6. En Mantenimiento, selecciona Restaurar respaldo completo, revisa la vista previa y confirma. La restauración está diseñada para una instalación sin operaciones. Tras restaurar, usa los usuarios y contraseñas del respaldo.
  7. Comprueba inventario, deudas, abonos y los últimos tickets antes de activar internet para esa sucursal.
  8. Si cambió la computadora o se retiró la vinculación, entra en Configuración central y pulsa Nueva clave en la misma sucursal. Configura esa clave en el POS ya restaurado. La clave vieja deja de funcionar.
  9. Espera la sincronización y compara los números. Si el respaldo es más viejo que las últimas ventas conocidas, detente y revisa: conectar una copia atrasada puede cambiar los reportes visibles.

Las credenciales cifradas de servicios pueden requerir volver a introducirse al cambiar de cuenta de Windows o de computadora. La clave de vinculación se guarda separada del respaldo portable; no se supone que un archivo de inventario restaure la conexión.

24 Desinstalar normalmente

En Windows 10, abre Configuración → Aplicaciones → Aplicaciones y características. En Windows 11, abre Configuración → Aplicaciones → Aplicaciones instaladas. Busca LunaDev POS y elige Desinstalar.

Selecciona conservar datos si reinstalarás el mismo negocio. Para retirar las versiones anteriores que no aparecían en Windows, abre el desinstalador descargado directamente. Si el programa todavía tiene un turno abierto, ciérralo antes de continuar.

No elimines manualmente carpetas de bases de datos ni las de otro sistema para resolver una actualización. El respaldo automático local no protege contra formatear todo el disco: cópialo fuera del equipo.

25 Facturación

Menú → Facturación · Pruebas contiene el entorno sandbox. La emisión real está desactivada. No uses un XML de prueba como factura fiscal para un cliente.

Crea una cuenta sandbox en https://dev.facturama.mx, configura el emisor de pruebas según el proveedor e introduce esas credenciales en Configuración fiscal. Revisa la clasificación SAT e impuestos de cada producto con tu contador antes de probar la factura individual, global, complementos de abonos o devoluciones.

Una respuesta incierta se consulta antes de reintentar, para evitar duplicar. Una devolución del inventario no cancela automáticamente el CFDI. Casos no admitidos requieren revisión fiscal y no se fuerzan. Todavía está pendiente probar tu cuenta externa de timbrado; la emisión de producción requiere una validación posterior y los requisitos fiscales del negocio. Información oficial del SAT.

26 Si algo no funciona

  • Veo datos viejos tras instalar: probablemente conservaste los datos o abriste una versión anterior. Cierra el programa y usa el recorrido de instalación limpia; guarda el respaldo.
  • La página del dueño no muestra esta prueba: comprueba el local seleccionado, la URL, su clave y el estado de sincronización. El correo por sí solo no enlaza el POS.
  • Credenciales incorrectas en la página: usa correo y clave central. No pruebes la contraseña de Cloudflare o la del mostrador como si fueran la misma.
  • Cloudflare error 1033: corresponde al túnel temporal, no al enlace fijo de Workers. Revisa si abriste un enlace antiguo trycloudflare.com; para esta configuración usa el enlace central fijo.
  • El historial se está sincronizando: espera varios ciclos y verifica internet; no crees otra sucursal para esconder el aviso.
  • No puedo cerrar: revisa si queda turno abierto. Cierra el corte con efectivo contado. La recuperación de un turno requiere una cuenta autorizada.
  • No acepta mi Excel: conviértelo a CSV y comprueba las ocho columnas. No cambies solo la extensión de un archivo binario.
  • Hay sobrante o faltante: compara efectivo físico, fondo, ventas en efectivo, abonos, devoluciones, entradas y salidas; tarjeta y transferencia no están en el cajón.
  • La ganancia difiere del sistema anterior: revisa costos históricos, descuentos, devoluciones y si estás comparando margen antes de comisión con ganancia después de comisión.
  • No aparece para desinstalar en Windows: usa la herramienta independiente para la versión antigua e instala la nueva entrega que ya registra la aplicación.

Antes de repetir un cobro, busca su ticket para saber si se guardó. Conserva el mensaje de error y el contexto; no compartas contraseñas, claves de sucursal ni RFC privados en capturas públicas.

27 Qué conserva cada tipo de archivo

Inventario CSV o XLS de texto: catálogo y stock agrupados; no ventas, usuarios, deudas ni conexión.

Inventario JSON de LunaDev: catálogo y lotes compatibles; no todo el negocio.

Excel completo del historial: reportes del periodo y cinco vistas; no sirve para restaurar la base operativa.

Respaldo completo .botica.json: datos internos del negocio, usuarios con contraseñas protegidas, clientes, deudas, abonos, ventas, stock, cortes, configuración y registros fiscales compatibles.

Carpeta datos-originales: copia archivada de los archivos originales, incluida la vinculación. Es una recuperación adicional; restaurar una vinculación vieja no sustituye pedir una clave nueva al cambiar de equipo.

D1 en Cloudflare: copia de consulta central. No es una copia completa restaurable del POS.

28 Revisión antes de entregar a otro negocio

Comprueba que la instalación nueva pide crear su cuenta, que stock y operaciones empiezan vacíos, que utiliza su nombre/logo y que no contiene tus claves. Usa su página central y una clave distinta para cada sucursal. Verifica impresión, escáner, cobro, abono, devolución, corte y restauración de un respaldo de prueba antes de depender de él durante la jornada.

Conserva el proyecto fuente y sus herramientas de publicación separados de los datos de cada cliente. Instalar actualizaciones debe conservar datos. Empezar de cero debe ser una elección consciente, con respaldo. La marca LunaDev POS todavía no tiene una verificación de disponibilidad de marca dentro de este trabajo.
